这个工作空间做 **1 分钟情景 MV**：以管理员上传的一到两位人物的形象照为准，围绕一首歌做约 60 秒的情景 MV——歌曲分析与卡点表、多版故事板比较选优、定妆、情境脚本、分镜表、逐镜首帧与视频片段、按拍点裁切并铺上歌曲的粗剪与交付清单。除非管理员另有要求，按下面的规程做。

### 前提
- 先看 `media/` 里的素材：形象照（每人至少一张，正面清晰）、歌曲（`mp3` / `wav` / `m4a` 等音频文件）与歌词 / 说明（`docs/` 或指令里）。把每位人物的不变特征（脸型、发型、发色、体型、肤色、眼镜、纹身等标志物）写进 `agent/PROJECT.md`。
- **人物形象不可改**：脸、发型、体型要认得出是形象照上的人。每次生成都把这个人的形象照（有定妆图后再加定妆图）放进 `reference_images`，生成后用 `view_image` 对照原图检查，不像就重来（一条指令里最多 3 次），仍不行就换景别（背影、剪影、远景、手部与道具特写）绕开。两位人物同框时两人的形象照都带上。
- **歌曲是 MV 的唯一音轨，也是剪辑的时间轴**：先分析歌曲，再构思画面（流程第 1 步）。设备没有作曲、配音或人声工具，不要生成歌曲；没上传歌曲时在回复里请管理员上传，同时先做故事板方案与定妆，分镜按管理员给的时长、BPM 与段落估算，歌曲到位、分析完再校准。
- 不做对口型：视频模型听不到歌，嘴型对不上。人物用表演、走位、眼神与环境叙事，不正对镜头唱；管理员点名要唱歌镜头时用侧面、远景或 2 秒以内的快切。视频片段自带的音轨在粗剪里不保留，模型有 `generate_audio` 参数时可传 `false`。
- **每张首帧、每段视频都要过物理与常识检查**（见下文），不通过就重做，有破绽的素材不进粗剪。

### 结构
- 总长约 60 秒：从歌曲里选一段约 60 秒作 MV 选段（管理员指定入点就用它，没指定就取副歌所在的一段并在回复里说明入点 / 出点），入点落在小节首拍，出点落在乐句结束处。
- **用足视频模型的单次时长**（「可用的生成模型」一节里 `duration` 的上限），不要把全片切成三五秒的短镜头。镜长取整数小节，常用一个乐句（4 或 8 小节；120 BPM 时 4 小节 = 8 秒）：前奏、主歌用 8–15 秒的长镜头，靠运镜、走位与镜内动作推进；副歌可以更密，但一镜仍是一个完整的动作（通常 4–8 秒）；3 秒以内的快切只放在段落切换、鼓点加花、drop 等强卡点上作点缀，全片不超过 4 个。60 秒通常 6–10 镜。
- 长镜头不是拿空镜拖时长：每镜写清起势、发展与落点，中途至少有一次运镜或动作的变化。超过单次上限的连续镜头，模型有 `extend`（延长）操作就续写，否则取末帧作下一段的 `first_frame` 接续。
- **卡点**分两层：切点落在卡点表里的小节首拍或段落切换上；镜内的关键动作（转身、抬头、推门、灯亮、镜头急推）落在重拍上。视频模型听不到歌，提示词里按秒写动作时刻（如「第 3 秒转身」），生成时长在镜长之外多留约 1 秒余量（不超过上限），粗剪时调整片段入点，把动作对到拍点上。
- 情境是一个小故事：地点、时间、两人的关系（或一个人的心境）、情绪弧与结尾，每一镜推进一点，不是换场景摆拍。无台词。主歌用单人镜头与环境铺情绪，副歌动作最大、两位人物同框，尾声一个收束镜头，结尾留 1–2 秒给结束卡。

### 流程（每步完成都更新 `agent/PROJECT.md` 的进度表）
1. **歌曲分析与卡点表**（先于一切创意）：
   - 用 `ffprobe` 读时长与采样率；出一张波形图（`ffmpeg -nostdin -y -i media/<歌曲文件> -filter_complex "showwavespic=s=1600x240:split_channels=0" -frames:v 1 media/song-wave.png`），用 `view_image` 看各段的能量起伏。
   - 取能量包络：`ffmpeg -nostdin -i media/<歌曲文件> -af "aresample=44100,lowpass=f=160,asetnsamples=n=882:p=0,astats=metadata=1:reset=1,ametadata=print:key=lavfi.astats.Overall.RMS_level:file=agent/song-low.txt" -f null -` 得到每 20 毫秒的低频（底鼓）能量；去掉 `lowpass=f=160,`、改写到 `agent/song-rms.txt` 再跑一遍，得到全频能量。
   - 用节点上的 `python3`（没有就用 awk）写个小脚本读这两个文件：把 dB 换成线性能量，取正向差分作起音强度，做自相关，在 60–180 BPM 之间找峰得到 BPM；再按拍长找起音强度累计最大的相位，得到拍点网格；按 4/4 拍每 4 拍取一个小节首拍（取重音最强的相位）；全频能量持续抬升或回落的地方结合歌词定段落边界；另记强卡点（鼓点加花、停顿、drop、人声进入）。管理员给了 BPM、带时间轴的歌词（LRC）或段落说明时以它为准校对。
   - 写 `docs/music.md`：BPM、拍号、小节时长；段落表（段落 | 起止时间 | 小节数 | 能量 / 情绪 | 配器与人声变化）；选段的入点 / 出点；**卡点表**（时间 | 类型：小节首拍 / 段落切换 / 重拍 / 加花 / 停顿 / drop | 强度 | 用途：切镜 / 镜内动作 / 光影变化）。定下选段以后，时间一律写 **MV 时间**（从选段入点起算，0 秒即入点）。
   - BPM 与段落时间点的摘要写进 `agent/PROJECT.md` 的「歌曲」栏。估算把握不大（节拍不稳、无鼓段、变速）时在回复里说明，改以段落与人声乐句作切点。
2. **故事板方案（多版比较选优）**：读歌词与 `docs/music.md` 后写 `docs/storyboard-options.md`：
   - 至少 3 版**明显不同**的方案：核心设定、叙事结构或视觉母题不同，不是同一个故事换个地点。每版写：一句话情境（谁、在哪、什么关系、情绪怎么变、结尾）；**记忆点**（一个观众看完记得住的画面或设计，如一个贯穿全片的道具或母题、一种特别的视角或结构、一处与歌词呼应的巧思）；视觉风格（画风、色调、光线、镜头语言）；按段落的粗分镜（每镜一行：MV 时间、镜长、画面一句话、卡点怎么用）；风险（常识漏洞、生成难点、人物一致性）。
   - 避开套路画面（雨中奔跑、海边看夕阳、天台吹风、咖啡馆对视等），要用就给出新的处理。特色来自设定、视角、结构与细节，不来自违反常识的奇观；选超现实风格时全片用同一套设定，并在设定内自洽。
   - 逐版自查常识：时间、地点、天气、光线前后一致；人物行为符合身份、关系与场合；因果成立（先有动机再有动作，道具先出现再使用）；空间走位连贯。
   - 比较表按五项打分（1–5）：贴合歌曲（歌词意象、情绪曲线、节奏）、特色与记忆点、常识与可信、可生成性（视频模型擅长单一主体的清晰动作与稳定运镜，不擅长复杂的手部交互、多人肢体纠缠、画面文字、高速大幅动作、镜面反射）、卡点表现力。写明选哪一版、为什么，可以吸收别版的长处合并。
   - 选中方案的一句话情境、记忆点与视觉风格写进 `agent/PROJECT.md`；`docs/treatment.md` 写成给管理员看的情境脚本（情境、段落对应的画面走向、人物造型）。
3. **定妆**：按选中方案给每位人物生成**定妆图** `media/char-<名>.png`（形象照作 `reference_images`，正面半身、干净背景，MV 里的服装与发型），两位人物再出一张同框定妆 `media/char-duo.png` 锁定身高差与站位。在回复里列出各版方案的一句话与选择理由，请管理员确认方案与定妆。除非管理员一条指令里明确要求一口气做完，定妆与分镜批量生成分在不同指令里做。
4. **分镜表**：写 `docs/storyboard.md`，一张表，列固定为：镜号 | MV 时间（起–止） | 段落 / 小节 | 镜长 | 生成时长 | 人物 | 景别 / 运镜 | 画面描述 | 动作 / 情绪 | 镜内卡点 | 首帧文件 | 视频文件 | 状态。镜号 `s01`、`s02`…；切点取自卡点表，各镜镜长之和不少于选段长度；「镜内卡点」写「MV 时间 → 动作」，生成时换算成片段内的秒数写进提示词。写完按下文的物理与常识检查从头到尾过一遍（相邻镜头之间人物站位、光线、天气、服装、道具连续，走位不越轴），有问题先改表再生成。
5. **逐镜首帧**：按分镜表给每镜生成首帧 `media/s01-frame.png`…，`reference_images` 带上出镜人物的形象照、定妆图与同场景相邻镜头的首帧，保持人物、服装、场景一致；提示词写清景别、构图、光源方向，以及人物和环境的接触关系（站、坐、倚在什么上）。生成后用 `view_image` 做首帧检查（见下文），不通过就重做。
6. **逐镜视频**：以首帧为 `first_frame` 生成 `media/s01-clip.mp4`…，`duration` 取分镜表的生成时长；提示词只写这一镜按秒分解的动作、情绪与镜头运动，不重复描述外形，同一时刻的动作不超过两个。生成后拼一张覆盖全片的帧图（`ffmpeg -nostdin -y -i media/s01-clip.mp4 -vf "fps=1,scale=240:-2,tile=4x4" -frames:v 1 -update 1 media/s01-sheet.jpg`，每秒一帧，可盖住 16 秒），关键动作前后再拼一张密的（`ffmpeg -nostdin -y -ss <动作前 1 秒> -t 3 -i media/s01-clip.mp4 -vf "fps=4,scale=240:-2,tile=4x3" -frames:v 1 -update 1 media/s01-sheet-<秒>.jpg`），用 `view_image` 做视频检查（见下文），并记下镜内动作实际发生在片段的第几秒，粗剪对拍要用。接续镜头先取上一镜的末帧（`ffmpeg -nostdin -y -sseof -0.1 -i media/s01-clip.mp4 -frames:v 1 -update 1 media/s01-last.png`），再以它作 `first_frame`。
7. **粗剪**（节点上要有 ffmpeg，见「节点上的创作工具」）：
   - 先把每镜裁到镜长并统一参数：`ffmpeg -nostdin -y -ss <片段入点> -i media/s01-clip.mp4 -t <镜长> -an -vf "scale=<宽>:<高>:force_original_aspect_ratio=increase,crop=<宽>:<高>,fps=30,setsar=1" -c:v libx264 -crf 18 -pix_fmt yuv420p media/s01-cut.mp4`，宽高取多数片段的分辨率。片段入点 = 动作在片段里实际发生的秒数 − 这个动作在本镜里应落的拍点（从本镜起点算），要落在 0 到余量之间，超出说明动作偏得太多，重做或改拍点。镜长用相邻切点的 MV 时间相减；按 1/30 秒取整时以累计时间为准，免得误差累积。
   - 按播放顺序把 `file '../media/s01-cut.mp4'` 等条目写进 `agent/cut.txt`，拼成无声画面（`ffmpeg -nostdin -y -f concat -safe 0 -i agent/cut.txt -c copy media/picture-cut.mp4`），再铺歌曲选段：`ffmpeg -nostdin -y -i media/picture-cut.mp4 -ss <入点秒> -t <选段秒> -i media/<歌曲文件> -map 0:v -map 1:a -c:v copy -c:a aac -shortest media/rough-cut.mp4`；出点不在乐句的自然结束处时加 `-af "afade=t=out:st=<选段秒−2>:d=2"` 淡出。最后用 `ffprobe` 核对画面与音频时长一致。
   - 节点上没有 H.264 编码器时，退回在 `agent/cut.txt` 里给原片段写 `inpoint` / `outpoint`、用 `-an -c copy` 拼接；这样切点会落在关键帧附近，在交付清单里注明卡点精度受限。
   - 管理员给了歌词并要求字幕、且节点上字幕烧录可用时，再按 `docs/lyrics.md` 的时间点烧一版。
8. **交付**：`docs/delivery.md` 列出全部素材的路径与播放顺序、歌曲选段的入点 / 出点、BPM、总时长、每镜的检查结论与重做次数、未完成项与假设，并注明 `media/rough-cut.mp4` 是粗剪。

### 物理与常识检查（首帧与视频都要过，不通过就重做）
- **首帧**：人体结构（手指数、四肢与关节方向、头身比例）；尺度与透视（人与门、桌椅、车辆的大小关系，地平线与消失点一致）；光影（光源方向统一，影子与反射对得上，昼夜与室内外的光一致）；重力与接触（脚落在地上，坐姿有支撑，物体放在支撑面上，头发与衣物自然下垂）；物件常识（乐器、手机、雨伞、杯子的拿法与朝向正确，衣着与天气、季节相符，画面里没有乱码文字）。
- **视频**：人物与物体恒存（不凭空出现、消失、变形或多出一人，人数与道具前后一致）；运动（走路脚步交替，不滑步、不漂浮、不穿模，转身转头时身体不扭曲）；惯性与重力（头发、衣摆随动作摆动，掉落物往下落，液体与布料运动合理）；交互（手握住物体而不是穿过去，门先开人再过，先拿起再使用）；场景（背景建筑与家具不变形、不漂移，光线不无故跳变）；运镜连续（不中途跳切，空间不扭曲）；人物身份与服装全程不漂移。
- 不通过时先找原因再改：动作太复杂就拆成更少、更慢的动作并按秒写清；接触类出错就换景别避开手部，或在模型支持时加 `last_frame` 约束落点；场景变形就减小运镜幅度或改成固定镜头。一条指令里同一镜最多重做 3 次；只有开头或末尾一小段出错、剩下的部分仍够镜长时，粗剪里裁掉出错段也算通过；仍不行就改分镜（换景别、换动作）并在回复里说明。
- 检查结论写进分镜表的「状态」列（如「通过」「重做 2 次后通过」「裁掉 9–11 秒」）。

### 一致性与取舍
- 人物像不像、物理与常识是否正确，优先于单镜画质与镜头长度；长镜头保不住这两条时，宁可拆成两镜。
- 两位人物的镜头数与出镜时长大致均衡，管理员另说了主次就按主次。
- 未指定时缺省竖屏 9:16；模型不支持所需比例或时长就按最接近的取值生成并在回复里说明。
- 每条指令结束前更新 `agent/PROJECT.md` 的分镜进度（镜号 → 首帧 / 视频 / 检查状态）与「下一步」。
